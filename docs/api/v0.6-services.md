# Version 0.6 unified sessions and safe workflows

Snapshot date: 2026-08-23

Version 0.6 joins the controller-aware v0.5 domains behind one reusable API.
It changes no CLI syntax and adds no GUI or Home Assistant policy.

## Controller session

`ControllerSession` owns the transport and exposes the detected identity,
exact profile, capability map, monitor state, and connection metadata.

```python
from openmaxfire import ControllerSession

with ControllerSession.connect("/dev/ttyUSB0") as stove:
    print(stove.identity.to_dict())
    snapshot = stove.poll_snapshot(request_delay=0.10)
    backup = stove.configuration_backup_document(request_delay=0.10)
```

If no baud is supplied, connection setup probes 9,600 then 19,200 using only
the established identity reads. Unknown identities raise
`UnsupportedControllerError`; they are not coerced into the nearest profile.
The context manager owns and closes the transport.

`poll_snapshot()` queries CR00-CR0E and passes every addressed, telemetry, and
status frame through the same `MonitorState`. `iter_snapshots()` provides a
bounded or continuous synchronous subscription without printing or choosing a
client-specific representation.

## Read-only Checkout

```python
from openmaxfire import ReadOnlyCheckoutRunner

runner = ReadOnlyCheckoutRunner(stove)
result = runner.run_test(11, timeout_seconds=10)  # wait for door-open predicate
identity_results = runner.run_tests((1, 2, 3))
report = runner.report(identity_results)
```

The runner automates tests 1-8, 11-14, 16, 33-34, and 36-37. Tests 1-3 cover
communication, full EEPROM checksum, and controller/EEPROM data-format
matching. Passive tests poll only the exact registers used by their recovered
predicates. A timeout after valid mismatching reads is `fail`; no valid response
is `indeterminate`.

Manual and actuator tests return `not_run`. This is intentional: the API cannot
infer that an LED, fan, motor, igniter, wire, or thermocouple behaved correctly
without an established observation provider.

## Simulator-only configuration execution

```python
from openmaxfire import (
    ControllerSession,
    execute_configuration_plan,
    plan_configuration_update,
)

with ControllerSession.simulated(allow_writes=True) as stove:
    current = stove.read_configuration_image()
    plan = plan_configuration_update(
        current, {"fuel_a.fan.level_1": 0x42}, stove.profile
    )
    result = execute_configuration_plan(stove, plan, authorize=True)
    assert result.verified
```

The executor rereads A00-AFF before the first write and refuses a stale plan.
It hashes that exact pre-write image, applies verified A writes, invokes CW01 so
firmware recomputes A00/A01, rereads all 256 bytes, and requires the complete
target image plus a valid checksum. Explicit authorization is required.

A non-simulated session raises `CapabilityUnavailableError` before any write.
Changing a session's capability enum or supplying `authorize=True` cannot
bypass that backend gate.

## Simulator-only normal control

`execute_control()` builds a fresh idempotent plan and verifies the resulting
typed operating state. It enforces an in-session rate limit and blocks non-OFF
commands when the firebox door or ash drawer is open. Outcomes distinguish
already-satisfied and verified behavior from an indeterminate result.

The simulator models OFF, ON/startup, UP, and DOWN state transitions. Physical
sessions remain blocked until those commands and recovery timing are validated
on the controller.

## Simulator-only Checkout cleanup

`execute_simulated_checkout()` can exercise only reconstructed actuator plans
that also have a proven cleanup command. It requires explicit authorization
and a simulated backend. Cleanup runs from `finally`, so it is attempted after
success, failure, cancellation-like observer errors, or exceptions. Missing
action sequences or cleanup are hard blockers.

This validates workflow structure; it is not evidence that physical hardware
responds correctly.

## Evidence boundary

Real sessions can detect, identify, monitor, read registers/EEPROM, create
backups, and run the read-only Checkout predicates. Configuration, normal-
control, and actuator Checkout execution are hard-limited to
`SimulatedTransport`. Firmware loading remains separate and unsupported.

The portable suite contains 116 passing offline tests. The new tests cover
automatic session detection, typed telemetry ingestion, cached Checkout
backups, authorization refusal, stale-plan rejection, whole-image verification,
door interlocks, verified state changes, and cleanup after observer failure.
