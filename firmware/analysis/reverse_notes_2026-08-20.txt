Bixby 2.71 firmware - initial reverse engineering notes
=======================================================

MCU
---
PIC16F877A.

UART
----
Startup at 0x1825 configures:
  SPBRG = 0x20
  TXSTA = 0x26
  RCSTA = 0x90
If Fosc is 20 MHz, this corresponds closely to 38400 baud, 8N1 async serial.

Protocol parser
---------------
At 0x10E8 the firmware compares the first character against 0x43 ('C').
At 0x10F4 it compares the second character against 0x57 ('W').
At 0x120E it compares the second character against 0x52 ('R').

The parser therefore directly confirms:
  CRxx    -> read byte/register xx
  CWxxYY  -> write YY to byte/register xx
where xx and YY are ASCII hexadecimal.

The firmware includes an ASCII-hex decoder around 0x0F60 and a two-digit byte parser at 0x0F7C.
Responses are transmitted as ASCII hex and terminated with LF (0x0A).

CR register map - confirmed static handlers
-------------------------------------------
CR00 -> constant 0x00
CR01 -> RAM/state byte (bank1 0x53)
CR02 -> packed switch/input byte:
        bit0..2 = three multiplexed readings sampled via RD3
        bit3    = internal/mux state bit
        bit4    = RD0
        bit5    = RD1
        bit6    = RD4
        bit7    = RE1
CR03 -> packed status/output byte:
        bit0 = RB1
        bit1 = RB5
        bit2 = internal state bit (RAM 0x56 bit5)
        bit3 = internal state bit (RAM 0x56 bit7)
CR04 -> RAM byte 0x22
CR05 -> RAM byte 0x34
CR06 -> packed flags:
        bit0 = RAM 0x2D bit0
        bit1 = RAM 0x2D bit1
        bit2 = RB4
CR07 -> derived/scaled value from RAM 0x44/0x45
CR08 -> constant 0x07
CR09 -> RAM byte 0x2E
CR0A -> RAM byte 0x2F
CR0B -> constant 0x02
CR0C -> constant 0x71
CR0D -> constant 0x00
CR0E -> constant 0x00

Important hardware observation
------------------------------
TRIS configuration shows RD0, RD1, RD3, RD4, RE0, RE1, RB0, RB4, RB6, RB7 and RA0..RA5 are inputs at startup. RB1 and RB5 are outputs, even though CR03 reports their current states.

Door-state investigation
------------------------
The best direct digital-input candidates exposed through the existing CR interface are CR02 bits 4-7 (RD0/RD1/RD4/RE1) and CR06 bit2 (RB4). Static analysis does NOT yet prove which physical input is the firebox/hopper door switch. The next step is to trace these pins through the stove state machine and/or observe CR02/CR06 while physically operating each switch.
